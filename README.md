# DolceGllitBot — security & aliases update

Готовые исходники Telegram-бота. Установка Python на компьютере **не нужна**, если бот запускается на Docker-хостинге.

## Что изменено

- В обработчиках админ-кнопок `approve_join`, `decline_join`, `unmute` проверяется администратор, формат callback и наличие соответствующей незавершённой заявки/мута.
- Состояние заявок/одобрений/мутов сохраняется в `moderation_state.json` (в `DATA_DIR`).
- HTML-экранирование в `/dolcebest`; экранирование имён и пояснений в поздравлениях с днём рождения; безопасное отображение описания «Интуиции».
- Загруженный список `known_users` больше не сбрасывается и записывается на диск только при изменении имени/новом пользователе.
- Для «Угадайки» автоматически используются все русские и латинские варианты имён из `groups/intuitioninfo.txt`: `eunchae` → `ынче`/`ынчэ`, `chaewon` → `чэвон`/`чевон`, и т. д. В обеих играх нормализуются пробелы, регистр, `ё`.
- Команда администратора в личных сообщениях `/da_aliases eunchae ынче/ынчэ/eunchae` добавляет дополнительные ответы. Изменения сохраняются после перезапуска.
- Работает кнопка «Готово» в `/da`. Нужна хотя бы одна фотография. Временные папки раздельные для админов.
- Атомарное сохранение JSON, проверка реальной даты дня рождения, исправлены разрешения размута для aiogram 3.
- Docker: непривилегированный пользователь, определённые зависимости, правильный `.dockerignore`, без `chmod 777`.

**По просьбе владельца НЕ изменены:** значение `TOKEN`, ссылка-приглашение и `ALLOWED_LINK_CODE`, доступ к `/stopdolce` и `/dolcenext`.

## Залить на GitHub

Распакуй ZIP. Внутри — файлы репозитория, включая `main.py`, `photos/`, `groups/`, `Dockerfile` и `requirements.txt`. Загрузи файлы в корень репозитория, сохраняя структуру папок.

**Важно про приватные файлы:** старый публичный репозиторий уже содержит `known_users.json`, `birthdays.json`, `scores.json`, `activated_admins.json`, `dabest_excluded.json`. Их **специально нет в этом ZIP**. При загрузке через сайт GitHub существующие файлы сами не удалятся: **удали перечисленные файлы вручную из репозитория**. Обычная правка не удаляет их из старых коммитов — для полного удаления из истории требуется отдельная очистка истории Git. Не публикуй исходный ZIP с персональными данными.

## Сохранение существующих результатов

У тебя исходный ZIP содержит старые JSON-файлы. **Сохрани его только у себя.** Перед заменой хостинга перенеси нужные JSON-файлы в папку `DATA_DIR` на сервере (для Docker это `/app/data`), не в GitHub. Это сохранит очки, список пользователей и дни рождения. Для постоянного хранения данных в Docker смонтируй volume в `/app/data`.

Если используешь запуск напрямую без Docker, `DATA_DIR` по умолчанию равен текущему рабочему каталогу, так что старые JSON-файлы можно оставить рядом с `main.py` **только на сервере**.

`TOKEN` остался со значением из исходного проекта, как ты попросил. При запуске укажи рабочий токен в приватной копии/конфигурации — значение `Token` является заглушкой.

## Проверки

```bash
python -m compileall -q main.py
python -m unittest discover -s tests -v
```

Для запуска на хостинге нужны aiogram из `requirements.txt` и Telegram Bot API. Фактическую работу на живом боте нужно проверить после развёртывания.
